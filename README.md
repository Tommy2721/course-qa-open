# 课问 · 课程知识问答与复习助手

AIC 2026 算法主题赛（AI+开源）参赛作品，参赛方向（一）开源赋能的 AI 应用创新。
作品形态是网页应用，本地部署。

用法很简单：把课程课件丢进去，提问，拿到带页码出处的答案；课件里没有的东西，系统会直接说没有。

## 为什么要做这个

复习时最费时间的往往不是"不会"，而是"这句话到底在课件哪一页、它的前提条件是什么"。
直接去问通用聊天机器人也不行——它没读过我们的课件，答得挺像那么回事，页码和结论经常是编的。

所以我们做了个完全本地的方案：课件不出本机，生成用本地的开源模型，答案必须能落回课件原文。具体是四件事：

- 每条结论后面标 `[1][2]`，点开能看到课件第几页的那段原文
- 课件里没讲的内容直接拒答，不给"大概是"这种回答
- 答案生成完，再拆成一句句回原文找依据；找不到的自动改一次，改不动就显式标出来
- 反复问到的知识点会被记录，最后能导出一份复习清单

其中第三条是我们花时间最多的地方。普通 RAG 保证的是"检索到的段落相关"，我们要保证的是
"答案里每句话真的被原文支持"——这两件事不是一回事，模型写上 `[1]` 也不代表[1]里真有那句话。

## 检索链路

从上到下 8 个环节，每个环节都能单独开关，关掉就能跑一次消融，看看它到底有没有用。

| # | 环节 | 解决什么 |
|---|---|---|
| 1 | 向量召回 + BM25 召回，用 RRF 按排名融合 | 向量搜不到专有名词和编号，BM25 搜不到同义表述；两路分数量纲不同，不能直接加权相加 |
| 2 | 查询扩展：用本地模型把口语问题改写成几条检索式 | 学生问"学习率调太大会怎样"，课件里写的是"震荡发散"，词面对不上两路都会失手 |
| 3 | 交叉编码器重排 | 双塔检索精度有限，把"问题+段落"一起送进网络打分更准，重排分同时给拒答阈值用 |
| 4 | 章节感知分块 | 按固定长度硬切，会把公式和它的前提条件切到两个块里 |
| 5 | 小到大检索：小块负责检索，命中后扩成整节送模型 | 结论检出来了，但它成立的前提在上一段，模型看不到就会说错 |
| 6 | MMR 去冗余（默认关） | 章节内相邻块高度重叠时避免浪费上下文。我们这批语料上实测是负收益，见"已知问题" |
| 7 | 两级拒答：最高重排分阈值 0.44 + 答案级检测 | 光看分数覆盖不了"检索到了相关段落、但段落里根本没有答案"的情况 |
| 8 | 答案逐句核验：断言拆分 → 向量粗筛 → 重排精算 → 标出无依据结论 | 这是上面说的第三点，也是我们真正的自研部分 |

跑消融：`python -m src.eval --mode retrieve`。

## 技术栈

全部开源，许可证都核对过（完整 16 项见 `开源及第三方资源使用清单.md`）。

| 用途 | 组件 | 许可证 |
|---|---|---|
| 大模型 | Qwen2.5-7B-Instruct（Ollama 本地跑） | Apache-2.0 |
| 向量模型 | BAAI/bge-m3 | MIT |
| 重排模型 | BAAI/bge-reranker-v2-m3 | Apache-2.0 |
| 向量库 | Chroma | Apache-2.0 |
| 关键词检索 | rank_bm25 | Apache-2.0 |
| 中文分词 | jieba | MIT |
| 文档解析 | pdfplumber / python-pptx / python-docx | MIT |
| 界面 | Streamlit | Apache-2.0 |
| 推理服务 | Ollama | MIT |

PDF 解析原本打算用 PyMuPDF，后来发现是 AGPL-3.0，用作网络服务可能要求整个项目跟着以 AGPL 开源，
跟我们的 MIT 计划冲突，就换成了 MIT 的 pdfplumber。这个评估过程记在资源清单第 13 项。

## 快速开始

```bash
# 1. 虚拟环境
python -m venv .venv
source .venv/Scripts/activate      # Git Bash；PowerShell 用 .venv\Scripts\Activate.ps1

# 2. 依赖
python -m pip install -r requirements.txt

# 3. 装 Ollama 并拉模型（细节见 复现说明.md）
ollama pull qwen2.5:7b-instruct

# 4. 起界面：双击 启动界面.bat
#    到「课件管理」页签上传 PDF/PPT/Word → 点「保存并重建索引」
#    再回「向课程提问」页签提问
```

命令行方式（调试用）：

```bash
python -m src.index                        # 建索引
python -m src.answer "你的问题"             # 命令行问答
python -m src.eval --mode retrieve         # 检索消融，不需要 LLM，很快
python -m src.eval --mode full             # 全流程，含答案核验，慢
```

## 界面

一共五个页签：

- **向课程提问**：答案带 `[1]` 引用，出处能展开定位到课件原文；没有的内容直接拒答
- **学习分析**：从提问记录里找薄弱知识点，一键导出复习清单
- **检索调试**：两路召回和重排的分数全部摊开，可以现场关掉某一层看差别
- **课件管理**：界面上传和删除课件，一键重建索引
- **项目速览**：作品说明和分工

另外有历史对话，新建对话时自动归档，左边的侧栏能翻回任意一次。

## 已知问题

写在这里是因为报告里也这么写的，藏起来没意义。

- **MMR 和查询扩展这两层，在我们这批语料上没有提升**，默认关闭。语料只有 116 个块、来自同一门课的 5 份课件，
  同章节的冗余本来就少，这两个设计吃不到该吃的收益。消融数据在 `eval/results/`，负结果照原样放了。
- **可回答的题里有 8/85 被误拒**（9.4%）。第二级答案级检测偏保守，这是有意的取舍：教学场景里
  编个答案比不回答危害大得多。想放宽就得改检测逻辑，我们没来得及做。
- **核验器自身也会误判**。第二轮人工抽查里，被标为"无依据"的结论只有 26.5% 与人工判断一致，
  其余多数是误报——依据其实在课件别的页，只是不在本次检索上下文里。所以 9.4% 我们只敢说成
  "系统标记率"，不能说是真实未支持率。要改就得把取证范围从检索上下文扩到全课件。
- **只支持有文字层的课件**，扫描版 PDF 得上 OCR。
- **首次提问要等模型加载**，冷启动几十秒，之后正常。

## 公开范围说明

这个仓库是作品的公开成果仓库，包含：完整代码、自建 104 题评测集（含标准出处页码，拟以 CC BY 4.0 开放）、
检索消融结果（`eval/results/retrieval_compare.csv`）、公开版核验抽查表（`docs/核验抽查表_公开版.csv`，
只留结论和页码，不含课件原文）、复现说明、第三方资源清单。

没有放进来的是这几样：

- **课程课件原文（PPT/PDF）和它的解析索引**。课件版权是授课老师的，不随仓库公开；把任意课件放进
  `data/raw/` 就能把整条流程跑一遍。
- **含课件原文摘录的完整核验抽查表和逐题答案文件**。这两份随参赛材料以受限方式提交了，评审需要核对可以另行提供。
- 运行缓存和模型权重（体积和许可证原因）。

这么处理是按大赛开放成果要求的条款来的，代码和评测集的可复用性不受影响。
